# Domain docs

## Read before exploration

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain terms.
- `docs/adr/` contains architecture decision records. Read those relevant to the work.

If these documents do not exist, proceed silently. Create them through domain-modeling work when terms or decisions are resolved, rather than adding empty scaffolding.

## Use domain language

Use glossary terms in code, tests, issues, and documentation. Note genuine vocabulary gaps for domain-modeling work.

## Surface decision conflicts

If a proposal conflicts with an ADR, name the ADR and explain why the decision should be reconsidered. Keep the existing decision authoritative until a replacement is agreed.
